# SIH 2026 Problem Statement Report

## 1. Problem Statement Overview

- **Problem ID:** 26172
- **Problem Title:** Ultra-Lightweight Keyword Spotting (KWS) on Edge
- **Organization:** Private Tech/IoT Company (Implied)
- **Category:** Hardware / Software
- **Theme:** IoT / TinyML
- **Difficulty Level:** Medium

### Problem Statement

> Voice-controlled IoT processing everything in the cloud is slow and privacy-invasive. The future is hybrid: edge handles wake-up, cloud handles complex speech. The goal is to build an ultra-lightweight Keyword Spotting (KWS) model running locally on a low-power device (<256KB RAM). Upon detecting a custom keyword, it instantly streams audio to a cloud ASR. Must use open-source frameworks (TinyML) and cannot use pre-trained global words like "Alexa".

### One-Line Summary

Train a custom AI wake-word model that fits on a tiny microcontroller, and when it hears the word, it records and sends the rest of the sentence to the cloud via Wi-Fi.

---

## 2. Problem Understanding

### What is the actual problem?

If your smart speaker records everything and sends it to the cloud 24/7, it wastes bandwidth and ruins privacy. It should only listen locally for a specific word (like "Hey SIH"), and ONLY THEN turn on the Wi-Fi to send the rest of your command. 

### Who faces this problem?

Smart home device makers, privacy-conscious consumers, and IoT manufacturers.

### Why is this problem important?

Enables cheap, low-power, battery-operated voice assistants that don't invade privacy.

### Existing Problems / Limitations

Most custom wake-word engines are proprietary (e.g., Porcupine, Snowboy). Open-source models are often too large to fit into 256KB of RAM on cheap microcontrollers.

---

## 3. Expected Solution

### What is SIH asking us to build?

1. A custom-trained ML model (TensorFlow Lite for Microcontrollers) that detects a specific word.
2. C++ firmware running on a microcontroller (like ESP32) that constantly listens to an I2S microphone using <10% CPU and <256KB RAM.
3. Upon detection, it opens a WebSocket/MQTT connection and streams raw audio to a server.
4. A simple Python server that receives the audio and runs a basic Speech-to-Text.

### Proposed Solution Concept

Use Edge Impulse or TensorFlow Lite to train a small CNN model on a custom keyword (e.g., "Namaste Robot"). Deploy this onto an ESP32 connected to an INMP441 microphone. When the ESP32 hears the keyword, it turns on an LED, starts streaming audio chunks via UDP/WebSocket to a local laptop running a Python Speech-to-Text script, which prints the spoken command.

### Key Features

- Custom TinyML Keyword Spotting model.
- Extremely low memory footprint (<256KB).
- Fast and seamless transition from offline KWS to online streaming.
- Open-source pipeline from data collection to deployment.

### AI / ML Requirements

- Is AI/ML required? Yes, TinyML.
- What models could be used? Depthwise Separable CNN (DS-CNN) or simple Audio MFCC classifiers.
- Is training required? Yes, on a custom recorded dataset of the keyword.

## 13. Innovation Opportunities

### How can we make this solution different?

1. Implement a ring-buffer in the ESP32 RAM so it sends audio from *slightly before* the wake word ended, ensuring no words are cut off.
2. Train it on a regional language wake-word (e.g., "Suno Machine").

### Possible Advanced Features

- Connect the Python server to actual smart relays so the command actually turns on a physical lamp during the demo.
